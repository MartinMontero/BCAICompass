# OWASP Top 10 security review — v1

Reviewed: 2026-10-29
Scope: the new search, action planner, shortlist, persistence, exports, playbooks,
navigation, build/test configuration, and their integration with the existing
static React site. The OWASP Top 10 (2021) categories are all included below.

## Findings resolved during review

1. **Spreadsheet formula injection in CSV exports (low, resolved).** Organization
   fields originate from external websites. A future sourced value beginning with
   `=`, `+`, `-`, or `@` could be interpreted as a formula when a CSV is opened in
   spreadsheet software. `shortlistToCsv` now prefixes formula-like cells with an
   apostrophe and retains normal CSV quoting. A regression test covers this case.
2. **Vulnerable build/test dependencies (high/critical in development tooling,
   resolved).** The baseline audit reported six vulnerabilities. Installing an
   older Vitest temporarily introduced additional advisories. Vite, Vitest, the
   coverage provider, and transitive packages were upgraded to patched compatible
   versions. The final `npm audit` reports zero vulnerabilities.
3. **Substring retrieval causing misleading matches (correctness/security
   boundary, resolved).** Search previously matched `fund` inside `fundamental`.
   Matching now uses complete normalized words/phrases. Location exclusions and
   human-learning intent are deterministic and tested. Search still makes no
   unsupported organization claims.

No open P0/P1 security or product defects remain in the reviewed workflows.

## A01 — Broken Access Control: PASS / not applicable

The delivered site is static and has no accounts, roles, private records,
server-side object references, or administrative endpoints. Shortlists contain
only IDs from the public verified dataset and remain in the visitor's browser.
There is no server-side authorization boundary to bypass. The open JSON/GeoJSON
exports are intentionally public; no private data is included.

## A02 — Cryptographic Failures: PASS

No passwords, payment data, personal accounts, API keys, tokens, or secrets are
collected or stored. No custom cryptography is used. Production transport is a
hosting concern; the existing headers require secure requests through
`upgrade-insecure-requests`. Browser storage contains public organization IDs and
the theme preference only.

## A03 — Injection: PASS

- There is no database, SQL construction, shell execution, template compilation,
  `eval`, `new Function`, `innerHTML`, or `dangerouslySetInnerHTML` in the new
  runtime code.
- React renders search text, plan text, and playbook drafts as text.
- Search is capped at 240 characters; playbook drafts at 50,000; shortlists at 50
  validated IDs.
- Stored JSON is parsed inside `try/catch` and sanitized against known IDs.
- CSV cells are quoted and formula-like values are neutralized.
- External organization/source links come from the unchanged verified dataset,
  not from visitor input.

## A04 — Insecure Design: PASS

The design avoids remote generated claims and third-party API credentials.
Search ranks only published fields and explains matches. General planning advice
is explicitly separated from sourced organization facts. Empty results are
labeled as coverage gaps rather than proof of nonexistence. Browser-only storage
and non-persistent playbook drafts are disclosed. Clipboard failure has a tested
download/manual fallback. Limits prevent unbounded local work.

## A05 — Security Misconfiguration: PASS

The existing `public/_headers` includes CSP, `nosniff`, frame denial, referrer and
permissions policies, COOP, `base-uri`, `form-action`, and `object-src` restrictions.
Production builds do not enable debug mode or expose stack traces. A missing
favicon found during Chromium testing was fixed, removing the only observed
first-party 404. Dependency installation and build scripts require no secrets.

## A06 — Vulnerable and Outdated Components: PASS

Final command: `npm audit`
Final result: 0 info, 0 low, 0 moderate, 0 high, 0 critical vulnerabilities.
The lockfile is versioned. Vitest and Playwright are development-only dependencies;
the production runtime remains React, Leaflet, and React-Leaflet.

## A07 — Identification and Authentication Failures: PASS / not applicable

There is no login, session, JWT, password reset, MFA flow, or authenticated
operation. The site does not simulate accounts. The shortlist is explicitly
browser-local and must not be treated as a private cloud-backed resource.

## A08 — Software and Data Integrity Failures: PASS with residual third-party note

- Local-storage JSON is not deserialized into executable objects; only string IDs
  present in the verified dataset survive validation.
- The trusted organization source file is protected by a byte-identical SHA-256
  acceptance check.
- Open-data exports are regenerated by the build and validated.
- No user-supplied URL is fetched, imported, or executed.
- The existing site loads Google Fonts and OpenStreetMap tiles from fixed HTTPS
  origins allowed by CSP. These remain third-party availability/integrity
  dependencies; dynamic Google Fonts CSS does not use SRI. No new third-party
  runtime origin was introduced.

## A09 — Security Logging and Monitoring Failures: PASS / not applicable

The static frontend has no authentication, privileged mutation, payment, or
server-side security event to audit. It intentionally sends no visitor search,
shortlist, or playbook content to a telemetry service. Runtime/page errors and
failed requests are checked in Chromium during verification. Server/platform
logging remains the hosting operator's responsibility.

## A10 — Server-Side Request Forgery: PASS / not applicable

There is no backend or server-side URL fetch. Search, plan construction, and
exports run locally. The browser requests only fixed application assets and the
pre-existing Google Fonts/OpenStreetMap resources; visitor text is never converted
into a request URL.

## Conclusion

All A01–A10 categories were reviewed. The static, credential-free architecture
removes entire classes of access-control, authentication, injection, logging, and
SSRF risk. Residual operational risk is limited to hosting configuration and the
pre-existing external font/map providers. Final automated dependency and browser
checks are recorded separately under `verifier/runs/`.
